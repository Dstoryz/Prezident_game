# 🚨 КРИТИЧЕСКИЕ ПРАВИЛА ДЛЯ АГЕНТОВ

## ⚠️ ВАЖНО: Читать перед любыми действиями!

### 🔴 КРИТИЧЕСКИЕ СИТУАЦИИ

#### 1. ЗАВИСАНИЕ КОМАНД ТЕРМИНАЛА
**Проблема:** Команды типа `curl`, `ping`, `tail -f` могут зависнуть в ожидании ответа
**Признаки:** Терминал не отвечает на команды, курсор мигает без возможности ввода
**Действия агента:**
- НЕ ЖДАТЬ больше 10 секунд
- Использовать таймауты: `curl --max-time 10`, `timeout 10 command`
- Если зависло - немедленно прервать: `Ctrl+C` или `killall process_name`
- Сообщить пользователю: "Команда зависла, прерываю выполнение"
- Предложить альтернативное решение

**Примеры правильных команд:**
```bash
# ✅ Правильно - с таймаутом
curl --max-time 10 http://localhost:8000/api/
timeout 10 ping google.com

# ❌ Неправильно - может зависнуть
curl http://localhost:8000/api/
ping google.com
```

#### 2. ЗАЦИКЛИВАНИЕ ПРОЦЕССОВ
**Проблема:** Бесконечные циклы, рекурсивные вызовы, бесконечные тесты
**Признаки:** Высокая загрузка CPU, повторяющиеся сообщения, процесс не завершается
**Действия агента:**
- Устанавливать лимиты времени: `timeout 30 script.sh`
- Добавлять счетчики в циклы: `for i in {1..100}; do ... done`
- Мониторить процессы: `ps aux | grep process_name`
- При зацикливании: `kill -9 process_id`
- Сообщить: "Обнаружено зацикливание, прерываю процесс"

**Примеры защиты от зацикливания:**
```bash
# ✅ Правильно - с лимитом
timeout 30 ./long_running_script.sh
for i in {1..100}; do echo "Step $i"; sleep 1; done

# ❌ Неправильно - может зациклиться
while true; do echo "test"; done
./script_without_limits.sh
```

#### 3. БЛОКИРОВКА РЕСУРСОВ
**Проблема:** Файлы заблокированы, порты заняты, база данных заблокирована
**Признаки:** Ошибки "Permission denied", "Address already in use", "Database locked"
**Действия агента:**
- Проверять доступность ресурсов перед использованием
- Освобождать ресурсы после использования
- Использовать `lsof` для проверки занятых портов
- При блокировке: `fuser -k port_number` или перезапуск сервиса

### 🟡 ПРЕДУПРЕЖДАЮЩИЕ СИТУАЦИИ

#### 4. МЕДЛЕННЫЕ ОПЕРАЦИИ
**Проблема:** Операции занимают больше ожидаемого времени
**Действия агента:**
- Устанавливать разумные таймауты
- Показывать прогресс: "Выполняется... 50%"
- Предупреждать о долгих операциях заранее
- Предлагать отмену: "Операция займет 5 минут. Продолжить?"

#### 5. ОШИБКИ СЕТИ
**Проблема:** Нет доступа к внешним ресурсам, API недоступны
**Действия агента:**
- Проверять доступность перед использованием
- Использовать fallback варианты
- Сообщать: "Сеть недоступна, использую локальные ресурсы"

### 🟢 ПРАВИЛА БЕЗОПАСНОСТИ

#### 6. ВСЕГДА ИСПОЛЬЗОВАТЬ ТАЙМАУТЫ
```bash
# ✅ Обязательно для всех команд
timeout 30 curl --max-time 10 http://api.example.com
timeout 60 python long_script.py
timeout 120 npm install
```

#### 7. МОНИТОРИТЬ ПРОЦЕССЫ
```bash
# Проверка активных процессов
ps aux | grep -E "(python|node|curl|ping)" | grep -v grep

# Завершение зависших процессов
pkill -f "curl.*localhost"
killall python 2>/dev/null
```

#### 8. ЛОГИРОВАТЬ ВСЕ ДЕЙСТВИЯ
```bash
# Логирование с временными метками
echo "[$(date '+%H:%M:%S')] Выполняю команду..." >> log.txt
command 2>&1 | tee -a log.txt
```

#### 9. ОБНОВЛЯТЬ TODO ЛИСТ
**Проблема:** TODO лист не отражает текущее состояние проекта
**Признаки:** Выполненные задачи остаются в TODO, новые задачи не добавлены
**Действия агента:**
- После выполнения любой задачи - обновлять TODO_CHECKLIST.md
- Отмечать выполненные задачи: `- [x] Задача выполнена`
- Добавлять новые задачи: `- [ ] Новая задача`
- Обновлять статус проекта: "Проект готов к тестированию"
- Сообщать пользователю: "TODO лист обновлен"

**Примеры обновления TODO:**
```bash
# ✅ Правильно - обновление после выполнения
echo "- [x] Исправлены ошибки типизации в EnhancedEconomicModel" >> TODO_CHECKLIST.md
echo "- [ ] Добавить новые тесты для экономической модели" >> TODO_CHECKLIST.md

# ❌ Неправильно - забыть обновить TODO
# Выполнил задачу, но не отметил в TODO
```

### 10. ПРИОРИТЕТ ЗАДАЧ ИЗ TODO ЛИСТА
**Проблема:** Агенты тратят ресурсы на тесты производительности вместо выполнения задач по проекту
**Действия агента:**
- Не запускать тесты производительности автоматически
- Всегда в первую очередь выполнять задачи из TODO_CHECKLIST.md
- Если задача не из TODO — согласовать с пользователем
- После выполнения каждой задачи — отмечать её в TODO
- Сообщать: "Выполняю задачи по TODO листу, тесты производительности не запускаю"

**Пример:**
```bash
# ✅ Правильно
# Выполняем задачи из TODO
# ❌ Неправильно
# Запускать тесты производительности без указания пользователя
```
