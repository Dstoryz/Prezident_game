# 📋 Система планирования и контроля темпа разработки

## 🎯 Методы определения темпа разработки

### 1. Story Points (SP) - Основной метод
**Принцип:** Оценка сложности задач в условных единицах

**Шкала сложности:**
- **1 SP** - Простая задача (1-2 часа)
- **2 SP** - Несложная задача (2-4 часа)
- **3 SP** - Средняя задача (4-8 часов)
- **5 SP** - Сложная задача (1-2 дня)
- **8 SP** - Очень сложная задача (2-3 дня)
- **13 SP** - Экстремально сложная задача (неделя+)

**Примеры оценки:**
```
Настройка Django проекта: 3 SP
Создание базовых моделей: 5 SP
Реализация API эндпоинта: 3 SP
Создание React компонента: 2 SP
Интеграция с API: 3 SP
Тестирование функциональности: 2 SP
```

### 2. Velocity Tracking (Отслеживание скорости)
**Формула:** Velocity = Количество выполненных SP за спринт

**Спринт:** 1 неделя (5 рабочих дней)
**Цель:** Определить среднюю скорость команды

### 3. Burndown Chart (Диаграмма сгорания)
**Принцип:** Визуализация прогресса по времени

**Метрики:**
- Осталось SP на начало дня
- Выполнено SP за день
- Прогноз завершения

## 📊 Система планирования для архитектора

### Еженедельное планирование (Спринт)

#### Понедельник - Планирование спринта
```
1. Анализ задач из бэклога
2. Оценка сложности в Story Points
3. Распределение задач между агентами
4. Установка целей спринта
5. Создание плана-графика
```

#### Ежедневные стендапы (Daily Standup)
```
Время: 10:00 каждый день
Длительность: 15 минут
Участники: Все агенты

Вопросы:
1. Что сделал вчера?
2. Что планируешь сегодня?
3. Есть ли блокеры?
4. Прогноз по завершению задач
```

#### Пятница - Ретроспектива спринта
```
1. Анализ выполненных задач
2. Расчет velocity
3. Выявление проблем
4. Планирование улучшений
5. Корректировка следующих спринтов
```

## 🎯 Шаблоны команд для архитектора

### Планирование задач
```
Архитектор-агент, создай план спринта на неделю [дата-дата]
Архитектор-агент, оцени сложность задачи [описание] в Story Points
Архитектор-агент, распредели задачи между агентами
Архитектор-агент, создай burndown chart для текущего спринта
```

### Контроль выполнения
```
Архитектор-агент, проведи daily standup
Архитектор-агент, проверь прогресс по задачам
Архитектор-агент, рассчитай velocity команды
Архитектор-агент, выяви блокеры и риски
```

### Корректировка планов
```
Архитектор-агент, пересмотри план из-за [причина]
Архитектор-агент, добавь задачу в текущий спринт
Архитектор-агент, перенеси задачу на следующий спринт
Архитектор-агент, перераспредели задачи между агентами
```

## 📈 Метрики и KPI

### Основные метрики
1. **Velocity** - SP/спринт
2. **Burndown Rate** - SP/день
3. **Task Completion Rate** - % выполненных задач
4. **Bug Rate** - количество багов/спринт
5. **Code Quality Score** - оценка качества кода

### Целевые показатели
```
Velocity: 20-30 SP/спринт (для команды из 4 агентов)
Task Completion Rate: >90%
Bug Rate: <5 багов/спринт
Code Quality Score: >8/10
```

## 🗓️ Шаблоны планов

### План спринта (шаблон)
```
СПРИНТ #1 (Неделя 1-7 января)
Цель: Создание MVP - базовая структура проекта

ЗАДАЧИ:
Фронтенд-агент:
- [ ] Настройка React проекта (3 SP)
- [ ] Создание базовой структуры компонентов (5 SP)
- [ ] Реализация главного экрана (8 SP)

Бэкенд-агент:
- [ ] Настройка Django проекта (3 SP)
- [ ] Создание моделей данных (5 SP)
- [ ] Реализация базовых API (8 SP)

Агент-тестировщик:
- [ ] Настройка тестового окружения (2 SP)
- [ ] Создание базовых тестов (3 SP)

ОБЩАЯ СЛОЖНОСТЬ: 37 SP
ЦЕЛЬ: Завершить 30+ SP
```

### Daily Standup (шаблон)
```
ДАТА: [Дата]
УЧАСТНИКИ: Архитектор, Фронтенд, Бэкенд, Тестировщик

ПРОГРЕСС:
Фронтенд-агент: Выполнил 3 SP, осталось 5 SP
Бэкенд-агент: Выполнил 2 SP, осталось 6 SP
Агент-тестировщик: Выполнил 1 SP, осталось 2 SP

БЛОКЕРЫ:
- Фронтенд-агент: Ожидает API от бэкенда
- Бэкенд-агент: Нет блокеров

ПЛАН НА ЗАВТРА:
- Фронтенд-агент: Интеграция с API (3 SP)
- Бэкенд-агент: Завершение API (3 SP)
- Агент-тестировщик: Тестирование интеграции (2 SP)
```
