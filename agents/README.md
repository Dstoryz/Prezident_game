# 📋 Чек-лист и инструкции для агентов проекта

## 1. CORS и разрешённые источники
- Всегда добавляйте все используемые адреса фронтенда (например, http://localhost:3000, http://localhost:3001 и т.д.) в CORS_ALLOWED_ORIGINS в backend/prezident_game/settings.py.
- После добавления новых портов или доменов — перезапускайте backend.

## 2. Порты и процессы
- Перед запуском серверов ОБЯЗАТЕЛЬНО проверяйте занятость портов:
  - Backend: 8000
  - Frontend: 3000 (или другой, если основной занят)
- Если порт занят — завершите процесс командой:
  ```bash
  # Остановка Django процессов
  pkill -f "python manage.py runserver"
  
  # Или для конкретного порта:
  fuser -k 8000/tcp
  kill $(lsof -t -i:3000)
  ```
- НЕ запускайте несколько экземпляров серверов на одном порту!
- Всегда используйте `is_background=True` для долгих процессов!

## 3. JWT-токены и авторизация
- После регистрации или логина всегда сохраняйте полученный токен (access/refresh) и используйте его для всех защищённых запросов.
- Проверяйте, что токен передаётся в заголовке Authorization:
  Authorization: Bearer <access_token>
- Если получаете 401 — проверьте актуальность токена и его наличие в localStorage/cookies.

## 4. Структура ответов API
- Все ответы backend должны содержать:
  - success (bool)
  - message (str)
  - game (dict, если это игровой API)
- Фронтенд должен быть готов к обработке ошибок и отсутствия некоторых полей (fail-safe).

## 5. Кастомная модель пользователя
- Если используется кастомная модель User без поля username:
  - В настройках Django отключите обязательность username:
    ACCOUNT_USERNAME_REQUIRED = False
    ACCOUNT_USER_MODEL_USERNAME_FIELD = None
  - Везде, где требуется username, используйте email.
  - Проверьте сериализаторы и формы на отсутствие поля username.

## 6. Перезапуск и кэш
- После любых изменений в настройках, моделях, CORS, API:
  - Перезапускайте backend и frontend.
  - Очищайте кэш браузера (Ctrl+F5).
- Проверяйте, что изменения вступили в силу (например, через curl или Postman).

## 7. Логирование и диагностика
- При ошибках 400/401/403/500:
  - Смотрите логи backend и консоль браузера.
  - Проверяйте структуру запроса и наличие токена.
  - Проверяйте CORS-заголовки в ответе.

## 8. Автоматизация и тесты
- Перед релизом или после крупных изменений:
  - Запускайте автоматические тесты (юнит-тесты, интеграционные).
  - Проверяйте цепочку: регистрация → логин → старт игры → получение профиля → logout.

## 9. Рекомендации по запуску
- Backend:
  ```bash
  cd backend
  # ОБЯЗАТЕЛЬНО остановить старые процессы!
  pkill -f "python manage.py runserver"
  python3 manage.py runserver 0.0.0.0:8000
  ```
- Frontend:
  ```bash
  cd frontend
  npm start
  # Если порт занят — соглашайтесь на запуск на другом порту и добавляйте его в CORS.
  ```

## 10. Документирование изменений
- Все изменения в настройках, моделях, API — фиксируйте в README или changelog.
- Обновляйте инструкции для команды и агентов.

## 11. БОРЬБА СО SCOPE CREEP
- **ГЛАВНОЕ ПРАВИЛО:** НЕ добавляйте новые фичи без четкого обоснования!
- Перед добавлением любой фичи задайте себе вопросы:
  1. Действительно ли это необходимо для MVP?
  2. Можно ли это реализовать проще?
  3. Не усложнит ли это понимание для пользователя?
  4. Есть ли ресурсы на поддержку этой фичи?

### История проекта "Президент":
- **Начало:** Простая экономическая модель (ВВП, инфляция, безработица)
- **Проблема:** "А давайте добавим сектора!" → "А давайте добавим сельское хозяйство!" → "А давайте добавим строительство!" → и т.д.
- **Результат:** Монстр с сотнями параметров, сложный в понимании и тестировании

### Решение:
- Выносите параметры в конфигурационные файлы
- Создавайте профили сложности (легкий, нормальный, сложный)
- Следуйте принципу KISS (Keep It Simple, Stupid)

## Обзор
Система состоит из 4 специализированных агентов, каждый из которых отвечает за свою область разработки.

## Агенты

### 🏗️ Архитектор-агент (Главный управляющий)
**Файл:** `architect_agent.md`
- Координирует работу всех агентов
- Принимает ключевые решения по архитектуре
- Контролирует качество и соответствие ТЗ
- Создает план разработки

### 🎨 Фронтенд-агент
**Файл:** `frontend_agent.md`
- Разрабатывает React-компоненты
- Создает пользовательский интерфейс
- Интегрирует с API
- Работает с графиками и визуализацией

### ⚙️ Бэкенд-агент
**Файл:** `backend_agent.md`
- Разрабатывает Django-приложение
- Создает REST API
- Реализует экономическую логику
- Работает с базой данных

### 🐛 Агент-тестировщик
**Файл:** `testing_agent.md`
- Выявляет ошибки и баги
- Тестирует функциональность
- Проверяет производительность
- Анализирует безопасность

## Как использовать

### 1. Запуск агентов
При обращении к агенту, используйте его роль:
```
Архитектор-агент, проанализируй ТЗ и создай план разработки
Фронтенд-агент, создай компонент GameDashboard
Бэкенд-агент, реализуй API для начала игры
Агент-тестировщик, проверь экономическую логику
```

### 2. Иерархия команд
- **Архитектор-агент** имеет право давать команды всем остальным агентам
- Остальные агенты выполняют задачи в своих областях
- Агент-тестировщик может проверять работу всех агентов

### 3. Процесс разработки
1. **Архитектор-агент** анализирует задачу и создает план
2. **Бэкенд-агент** и **Фронтенд-агент** работают параллельно
3. **Агент-тестировщик** проверяет качество на каждом этапе
4. **Архитектор-агент** координирует интеграцию
