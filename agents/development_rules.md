## ⚠️ ВАЖНО: ЭТИ ПРАВИЛА ОБЯЗАТЕЛЬНЫ ДЛЯ ВСЕХ АГЕНТОВ

### 🔥 1. УПРАВЛЕНИЕ ПРОЦЕССАМИ И ПОРТАМИ

**ПРАВИЛО:** Перед запуском любого сервера ОБЯЗАТЕЛЬНО проверять занятость порта!

```bash
# ❌ НЕПРАВИЛЬНО - запуск без проверки
python manage.py runserver 0.0.0.0:8000

# ✅ ПРАВИЛЬНО - проверка и очистка
pkill -f "python manage.py runserver"  # остановить старые процессы
python manage.py runserver 0.0.0.0:8000  # запустить новый
```

**ПРАВИЛО:** Всегда используй `is_background=True` для долгих процессов!

### 🔥 2. SCOPE CREEP - ГЛАВНЫЙ ВРАГ ПРОЕКТА

**ПРАВИЛО:** НЕ добавляй новые фичи без четкого обоснования!

#### История проекта "Президент":
- **Начало:** Простая экономическая модель (ВВП, инфляция, безработица)
- **Проблема:** "А давайте добавим сектора!" → "А давайте добавим сельское хозяйство!" → "А давайте добавим строительство!" → и т.д.
- **Результат:** Монстр с сотнями параметров, сложный в понимании и тестировании

#### КОНТРОЛЬНЫЕ ВОПРОСЫ ПЕРЕД ДОБАВЛЕНИЕМ ФИЧИ:
1. **Действительно ли это необходимо для MVP?**
2. **Можно ли это реализовать проще?**
3. **Не усложнит ли это понимание для пользователя?**
4. **Есть ли ресурсы на поддержку этой фичи?**

### 🔥 3. КОНФИГУРАЦИЯ И НАСТРОЙКИ

**ПРАВИЛО:** Все внешние параметры выноси в конфигурационные файлы!

```python
# ❌ НЕПРАВИЛЬНО - хардкод в коде
alpha = 0.3
beta = 0.7
gamma = 0.1

# ✅ ПРАВИЛЬНО - конфигурационный файл
from config.economic_config import ECONOMIC_PARAMS
alpha = ECONOMIC_PARAMS['alpha']
```

**ПРАВИЛО:** Создавай профили сложности (легкий, нормальный, сложный)

### 🔥 6. АРХИТЕКТУРНЫЕ ПРИНЦИПЫ

**ПРАВИЛО:** Следуй принципу KISS (Keep It Simple, Stupid)!

- Простота важнее сложности
- Читаемость важнее производительности (на этапе разработки)
- Модульность важнее монолитности

**ПРАВИЛО:** Разделяй ответственность!

- Модели - только данные
- Сервисы - только бизнес-логика  
- Views - только обработка запросов
- Конфиги - только настройки

### 🔥 7. ОБРАТНАЯ СОВМЕСТИМОСТЬ

**ПРАВИЛО:** Изменения не должны ломать существующий функционал!

- Добавляй новые поля как опциональные
- Используй миграции для БД
- Тестируй старые API endpoints

### 🔥 8. БЕЗОПАСНОСТЬ

**ПРАВИЛО:** Никогда не коммить чувствительные данные!

- API ключи в .env файлах
- Пароли в переменных окружения
- Конфиги с секретами в .gitignore

### 🔥 9. ПРОИЗВОДИТЕЛЬНОСТЬ

**ПРАВИЛО:** Оптимизируй только после профилирования!

- Не оптимизируй преждевременно
- Измеряй производительность
- Оптимизируй узкие места

### 🔥 10. КОММУНИКАЦИЯ

**ПРАВИЛО:** Объясняй изменения простым языком!
